# sandbox-rn

## Overview

[React Native](https://reactnative.dev/) sandbox, created with
`npx react-native init`. The app round-trips every data type that New
Architecture TurboModules support through native code on iOS, Android, and web,
including file I/O, and lists each case with its result. The web version is
available at [rn-sandbox.a2f0.net](https://rn-sandbox.a2f0.net). See
[development guide](docs/development.md#bridge-round-trip).

The production web app uses [CT click tracking](docs/click-tracking.md).
Native apps and local development do not initialize the tracker.

### Getting Started

Existing Husky checkouts should first follow the one-time
[hook migration](docs/tooling.md#hooks-and-validation).

```bash
mise install                 # Ruby, Node, and the tools in .mise.toml
bun install --frozen-lockfile
bundle install               # CocoaPods, fastlane, and RuboCop
cd ios
bundle exec pod install
```

[mise](https://mise.jdx.dev/) reads Ruby and Node versions from `.ruby-version`
and `.nvmrc`, which CI also uses; `.mise.toml` adds Gradle (for the wrapper
jar), [ShellCheck](https://www.shellcheck.net/), [Bun](https://bun.sh/),
[Emscripten](https://emscripten.org/) (for the web build of the C++ module),
and [Terraform](https://developer.hashicorp.com/terraform) (for
[Sign-in provisioning](docs/operations.md#sign-in)).
CI uses mise for Node, Bun, and ShellCheck. Emscripten reads its version from
`.mise.toml` through its dedicated setup action; Ruby, Java, and Gradle retain
their platform setup actions. Bun installs JavaScript dependencies from
`bun.lock` and runs package scripts; Node remains the runtime for React Native,
Metro, Jest, and other Node CLI tools. See
[Dependency upgrades](docs/dependency-upgrades.md#package-management) for
lifecycle-script trust and lockfile maintenance.

Agent guidance and validation commands are in [AGENTS.md](AGENTS.md).

### No binary files

Nothing binary is committed; the pre-push hook and CI reject it. See the
[tooling guide](docs/tooling.md) for checks and script ownership.

- **App icons** are rendered from `assets/brand/logo.svg` (the mark, on a
  transparent square) and `assets/brand/background.svg`: the iOS App Store
  icon, and the Android adaptive icon layers (background, foreground, and
  themed monochrome) plus legacy icons for Android 7. The `images` section of
  `agent-tool.json` declares each file's size, layers, and destination, and
  [agent-tool](https://github.com/a2f0/agent-tool/blob/main/docs/images.md)
  renders them after `bun install --frozen-lockfile`. Builds regenerate them
  when the sources change (an Xcode build phase and a Gradle task before `preBuild`),
  or run `sh scripts/build/buildImages.sh [ios|android]`. The outputs are gitignored.
- **Web favicons** (`favicon.svg`, `favicon.ico`, and `apple-touch-icon.png`)
  and the 1200×630 social preview image (`og-image.png`) are the app icon
  rendered by the `favicons` target into `web/public/`, which ignores them.
  `bun run web` and `bun run build:web` render them first with
  `bun run build:favicons`, and Vite serves and copies them into `web/build`.
- **The Gradle wrapper jar** is regenerated by `scripts/dev/ensureGradleWrapper.sh`,
  which `bun install --frozen-lockfile` (with Gradle installed, and not on CI),
  `bun run android`, the Detox Android builds, and the fastlane Android lanes
  run first. Android
  Studio reads `gradle-wrapper.properties` and doesn't need the jar.
- **Debug builds** are signed with the Android Gradle plugin's default debug
  keystore (`~/.android/debug.keystore`), which it creates when missing.

### Development

```bash
bun run android             # native Android app
bun run ios                 # native iOS app
bun run start               # Metro development server
bun run web                 # web development server
bun run build:web           # production web assets in web/build
```

The web app uses React Native Web and Vite. Its C++ TurboModule is compiled
with Emscripten by `bun run build:wasm`; web builds and Jest run it first.
The [development guide](docs/development.md) describes the native/web bridges,
WebAssembly caching, and Jest, Playwright, and Detox setup.

```bash
bun run test                # WebAssembly, Jest, auth helpers, and fastlane tests
bun run test:web            # Playwright (install Chromium first)
```

### Operations

```bash
bun run preview:deploy:web  # build and dry-run web assets
bun run deploy:web          # deploy to rn-sandbox.a2f0.net
bun run ios:build-release
bun run ios:upload-release
bun run ios:profiles
bun run android:build-release
bun run android:upload-release
```

The [operations guide](docs/operations.md) covers web deployment previews,
Google/Apple sign-in provisioning, fastlane tiers and lanes, store credentials,
and one-time store setup. Push and merge workflows validate without deploying.
